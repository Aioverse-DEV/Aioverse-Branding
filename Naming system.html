Brand Asset
Naming Convention

A complete restructure of the brand asset repository — unified kebab-case naming, folder taxonomy, rename mapping for all 40 files, ready-to-run Git script, and a production README.

Naming Pattern

{brand}-{category}-{variant}-{theme}[-{size}][-v{N}].{ext}
{brand}
aioverse aiotize
{category}
logo mark icon banner bg pfp cover color
{variant}
full wordmark rounded tagline grid gradient youtube facebook whatsapp gmail
{theme}
electric-aqua midnight-teal soft-white electric-blue gradient dark
{size} [optional]
2560x1440 820x312 300px
{v} [optional]
Used when multiple versions of the same asset exist. v1 v2 v3

Rules

01 All lowercase kebab-case

No spaces, no underscores, no CamelCase. Every segment separated by a single hyphen `-`.

02 Brand prefix always first

Every asset is prefixed with its brand entity: `aioverse-` or `aiotize-`. Font files use `font-` prefix instead.

03 No parentheses, dots, or special characters

Replace `(YouTube)` → `youtube`, spaces → hyphens, underscores → hyphens.

04 Versioning with v{N} suffix

When duplicates exist (e.g. two YouTube banners), use `-v1`, `-v2` before the extension.

05 Multi-format assets share the same base name

SVG and WebP of the same asset share identical base names. E.g. `aioverse-logo-electric-aqua.svg` and `.webp`.

06 Docs use readable kebab names

`Branding System.md` → `brand-system.md`. All docs go into `docs/` folder.
